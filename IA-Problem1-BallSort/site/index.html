A ideia em cinco passos

  1. Um estado é uma fotografia do jogo: que bolas estão em que tubos.

  2. Cada movimento legal transforma um estado num estado novo, a que chamamos filho.

  3. Os estados e os movimentos formam um grafo. O estado inicial liga-se aos filhos, que se ligam aos filhos deles, e assim por diante.

  4. Queremos o caminho mais curto até um estado objetivo: todos os tubos vazios ou cheios de uma só cor.

  5. O algoritmo do Tutorial 1 (procura de custo uniforme) examina sempre primeiro o estado com menor custo acumulado g. Como cada movimento custa 1, o primeiro objetivo que encontra é o que tem menos movimentos.

O código, método a método

Abre cada parte para ver o código e a explicação. Começa pelo BallSortLayout: é a parte que escreveste de raiz.

Ilayout.java: o contrato

interface Ilayout3 métodos que qualquer problema tem de ter 
interface Ilayout {
    List<Ilayout> children();  // estados alcançáveis com 1 movimento
    boolean isGoal(Ilayout l); // este estado é objetivo?
    double getK();             // custo do movimento que levou aqui
}

Uma interface é uma promessa: diz que métodos existem, mas não diz como funcionam. Cada problema (8-puzzle, Ball Sort…) escreve a sua versão.

BallSortLayout.java: as regras do jogo

Camposcomo os tubos são guardados 
private static final char EMPTY = 'E';
private int height;      // capacidade H de cada tubo
private char[][] tubes;  // tubes[t][k]: bola na posição k do tubo t (k = 0 é o FUNDO)
private int[] size;      // size[t]: quantas bolas tem o tubo t
  • Cada tubo é uma pilha: só se mexe no topo.
  • O fundo está em tubes[t][0] e o topo em tubes[t][size[t] - 1].
  • Exemplo, Sample 2: o tubo 0 é {R, B, R} (do fundo para o topo), com size[0] = 3.
Construtor BallSortLayout(String)lê o texto do input 
String[] rows = str.split("\n");          // parte em linhas
height = rows.length;
...
for (int r = height - 1; r >= 0; r--) {   // de BAIXO para CIMA
    String[] cells = rows[r].split(" ");
    for (int t = 0; t < nTubes; t++) {
        char c = cells[t].charAt(0);
        if (c != EMPTY) tubes[t][size[t]++] = c;  // empilha
    }
}
  • Lê as linhas de baixo para cima, porque a última linha do input é o fundo dos tubos.
  • tubes[t][size[t]++] = c põe a bola na primeira posição livre e depois soma 1 ao tamanho.
children()as regras de movimento 
for (int i = 0; i < tubes.length; i++) {          // tubo de origem
    if (size[i] == 0) continue;                  // vazio: nada para tirar
    char ball = tubes[i][size[i] - 1];             // bola do topo
    for (int j = 0; j < tubes.length; j++) {      // tubo de destino
        if (j == i || size[j] == height) continue;   // mesmo tubo ou cheio
        if (size[j] > 0 && tubes[j][size[j] - 1] != ball)
            continue;                               // topo de outra cor
        BallSortLayout child = clone();            // copia o estado
        child.tubes[i][--child.size[i]] = 0;        // tira da origem
        child.tubes[j][child.size[j]++] = ball;     // põe no destino
        children.add(child);
    }
}
  • Testa todos os pares origem i → destino j. Com T tubos há no máximo T × (T − 1) filhos.
  • Um movimento é legal se: a origem tem bolas, o destino não está cheio, e o destino está vazio ou tem no topo a mesma cor.
  • continue salta para o próximo par.
clone()cópia profunda 
char[][] t = new char[tubes.length][];
for (int i = 0; i < tubes.length; i++) t[i] = tubes[i].clone();
return new BallSortLayout(height, t, size.clone());

Em Java, os arrays são partilhados por referência. Sem copiar cada tubo, mexer no filho mexia também no pai e nos irmãos.

isGoal(Ilayout l)o jogo está resolvido? 
for (int t = 0; t < tubes.length; t++) {
    if (size[t] == 0) continue;             // vazio: ok
    if (size[t] != height) return false;     // meio cheio: não
    for (int k = 1; k < height; k++)
        if (tubes[t][k] != tubes[t][0]) return false;  // cores misturadas
}
return true;
  • Cada tubo tem de estar vazio, ou cheio e todo da mesma cor.
  • "Cheio" não chega: no Sample 2 o início tem dois tubos cheios, mas misturados.
  • O argumento l não é usado, porque o Main passa null: aqui o objetivo é uma condição, não uma configuração concreta.
toString(), equals(), hashCode(), getK()os métodos de apoio
  • toString(): escreve os tubos como no input, de cima para baixo, com E nos espaços vazios. É o que o Main0 imprime.
  • equals(): dois estados são iguais se têm as mesmas bolas nas mesmas posições.
  • hashCode(): um número calculado a partir das bolas. Estados iguais dão o mesmo número. O HashMap e o HashSet usam estes dois métodos para saber se um estado já foi visto.
  • getK(): devolve 1, porque cada movimento custa 1.

BestFirst.java: o algoritmo (igual ao do Tutorial 1)

class Stateum nó da procura
  • layout: a configuração dos tubos.
  • father: o estado de onde veio (null no inicial). Serve para reconstruir o caminho.
  • g: custo desde o início. g = g do pai + getK().
solve(s, goal)o ciclo principal 
abertos = new PriorityQueue<>(... ordenada por g);  // por examinar
fechados = new HashMap<>();                         // já expandidos
abertos.add(new State(s, null));                    // início, g = 0
while (true) {
    if (abertos.isEmpty()) return null;          // sem solução
    actual = abertos.remove();                    // o de menor g
    emAbertos.remove(actual.layout);
    if (actual.layout.isGoal(objective))
        return path(actual);                     // encontrou!
    sucs = sucessores(actual);                    // gera os filhos
    fechados.put(actual.layout, actual);
    for (State suc : sucs)
        if (!fechados.containsKey(suc.layout) && !emAbertos.contains(suc.layout)) {
            abertos.add(suc);                     // nunca visto: entra
            emAbertos.add(suc.layout);
        }
}
  • abertos: fila de prioridade que devolve sempre o estado de menor g.
  • fechados: estados já expandidos. Evita repetir trabalho e entrar em ciclos.
  • emAbertos: a única coisa acrescentada ao tutorial. Guarda os mesmos estados que estão em abertos, mas responde "já está lá?" de imediato. Perguntar isso à PriorityQueue obrigava a percorrê-la toda.
  • path(actual): sobe pelos father até ao início e inverte a ordem.
Porque é o mínimoOs estados saem de abertos por ordem de custo. Com todos os movimentos a custar 1, o primeiro objetivo que sai é o de menos movimentos. Com custo 1, isto é o mesmo que uma procura em largura (BFS).
sucessores(n)filhos com pai e custo

Transforma cada filho de n num State com pai n. Não gera o filho igual ao avô, ou seja, não desfaz o último movimento.

Main.java: dado pelo professor

main()lê, resolve, imprime

Lê H e T, lê H linhas, cria o BallSortLayout e chama solve(layout, null). Imprime o g do último estado do caminho, ou no solution found se o solve devolver null. Não se mexe neste ficheiro.
