Capítulo 1

O jogo

Há vários tubos. Dentro há bolas de cores. Cada tubo leva no máximo H bolas (H é a capacidade). O objetivo é arrumar as bolas para que cada tubo fique vazio ou cheio de uma só cor.

As cores usam letras: R vermelho, B azul, P roxo, Y amarelo, G verde. A letra E quer dizer espaço vazio (empty).

As 3 regras de um movimento

  1. Só se tira a bola de cima de um tubo. Um tubo é como uma pilha de pratos: não se tira o prato do meio.
  2. Não se põe uma bola num tubo cheio.
  3. A bola só pode cair num tubo vazio, ou em cima de uma bola da mesma cor.

Cada movimento custa 1. O programa tem de dizer o menor número de movimentos para resolver o puzzle.

Exemplos de movimentos (H = 3)

✓ Pode
→

O azul está em cima do tubo 0 e o tubo 1 está vazio. Um tubo vazio aceita qualquer cor.

✓ Pode
→

Vermelho em cima de vermelho: mesma cor, e o tubo 1 ainda tem espaço.

✗ Não pode

Mover o azul do tubo 0 para o tubo 1? Não: em cima do tubo 1 está um vermelho. Cores diferentes.

✗ Não pode

Mover o vermelho do tubo 0 para o tubo 1? Não: o tubo 1 já está cheio (3 de 3).

✗ Não pode

Tirar o vermelho do fundo do tubo 0? Não: só se tira a bola de cima, que é azul.

Quando está resolvido?

✓ Resolvido

Dois tubos cheios de uma cor, um vazio.

✗ Não resolvido

Os tubos estão cheios, mas as cores estão misturadas. "Cheio" não chega.

✗ Não resolvido

O tubo 0 está a meio. Cada tubo tem de estar vazio ou cheio.

Capítulo 2

As palavras que o professor vai usar

Cada palavra com o significado e um exemplo do nosso jogo.

Estado (ou configuração)

Uma fotografia do jogo num momento: que bolas estão em que tubo.

Exemplo: é um estado. Depois de mexer uma bola, temos outro estado.

Estado inicial

O estado que vem no input, antes de qualquer movimento.

Estado objetivo

Um estado resolvido: todos os tubos vazios ou cheios de uma só cor.

Exemplo:

Filho (ou sucessor)

Um estado que se obtém com um movimento a partir de outro. O estado de onde se partiu é o pai.

Exemplo: o pai tem 2 filhos: azul para o tubo 1, ou azul para o tubo 2.

Expandir um estado

Gerar todos os filhos desse estado.

Grafo de estados (espaço de estados)

Todos os estados possíveis, ligados por setas quando há um movimento de um para o outro. Resolver o puzzle é encontrar um caminho neste grafo.

Caminho

A sequência de estados desde o inicial até ao objetivo. O número de movimentos é o número de setas.

Exemplo: no Sample 2 o caminho tem 6 estados e 5 movimentos. A resposta é 5.

Custo k e custo acumulado g

k é o custo de um movimento (aqui sempre 1). g é a soma dos custos desde o estado inicial: quantos movimentos já foram feitos.

Exemplo: o estado inicial tem g = 0, os filhos dele g = 1, os netos g = 2.

Procura (search)

O método de ir gerando estados até encontrar o objetivo.

Não informada (cega)

A procura não usa nenhuma "pista" sobre o quão perto está do objetivo. Só conta movimentos. O enunciado obriga a isto: nada de heurísticas.

Heurística

Uma estimativa de quanto falta até ao objetivo (por exemplo, quantas bolas estão fora do sítio). É o tema do Problem 2. Aqui não se usa.

Procura de custo uniforme

Examina sempre primeiro o estado com menor g. É a que usamos. Com custo 1 por movimento, é igual à procura em largura (BFS).

abertos (open)

A lista de espera: estados já gerados mas ainda não examinados. Sai sempre primeiro o de menor g.

fechados (closed)

Os estados já examinados e expandidos. Servem para não repetir trabalho.

Padrão Strategy

Uma forma de organizar o código: o algoritmo fica de um lado e as regras do problema do outro, ligados por uma interface. Assim o mesmo algoritmo resolve problemas diferentes. Explicado no capítulo 5.

Capítulo 3

Do input aos tubos

O programa recebe texto e tem de o transformar em tubos. Vamos ver com o Sample 2.

O input 
3 3
R B E
B B E
R R E

A 1.ª linha diz H = 3 (capacidade) e T = 3 (número de tubos). Depois vêm H linhas, de cima para baixo. Cada coluna é um tubo.

Os tubos

A coluna 0 lida de cima para baixo é R, B, R. A coluna 1 é B, B, R. A coluna 2 é só E: está vazia.

Como o programa guarda isto

Usa duas coisas. Um array é uma fila de caixinhas numeradas a partir de 0.

  • tubes[t] guarda as bolas do tubo t, do fundo para cima. A caixinha 0 é o fundo.
  • size[t] guarda quantas bolas tem o tubo t.
tubes[0] = { R, B, R }   size[0] = 3     // fundo R, meio B, topo R
tubes[1] = { R, B, B }   size[1] = 3     // fundo R, meio B, topo B
tubes[2] = { _, _, _ }   size[2] = 0     // vazio
Truque para lembrar

A bola de cima do tubo t está sempre em tubes[t][size[t] - 1]. Exemplo: no tubo 1, size[1] = 3, por isso o topo é tubes[1][2] = B.

Porque é que o programa lê de baixo para cima?

Porque quer pôr primeiro o fundo do tubo, na caixinha 0. A última linha do input é o fundo, por isso começa por ela.

Capítulo 4

Como o computador procura, passo a passo

O computador não "vê" a solução. Experimenta movimentos de forma organizada: primeiro todos os estados a 1 movimento do início, depois todos a 2, depois a 3… O primeiro estado resolvido que encontra é, por isso, o de menos movimentos.

A receita (o algoritmo do Tutorial 1)

  1. Põe o estado inicial na lista abertos, com g = 0.
  2. Se abertos estiver vazia, não há solução. Fim.
  3. Tira de abertos o estado com menor g. Chama-lhe actual.
  4. Se actual estiver resolvido, encontrámos a resposta: o g dele. Fim.
  5. Senão, gera os filhos de actual e põe actual em fechados.
  6. Cada filho que nunca foi visto (não está em abertos nem em fechados) entra em abertos com g = g do pai + 1.
  7. Volta ao passo 2.

Vê a receita a funcionar

Escolhe um exemplo e carrega em "Passo seguinte". Em cada passo vês qual estado sai da lista, que filhos gera e como ficam as duas listas.

Passo 1 de 1 abertos: 0 estados fechados: 0 estados

abertos (próximos a sair)

fechados

Porque dá sempre o mínimo

Os estados saem de abertos por ordem de g: primeiro todos os de g = 0, depois todos os de g = 1, depois g = 2… Se existisse uma solução com menos movimentos, teria saído antes.

Porque é preciso fechados

Sem ela, o programa podia andar às voltas: mover uma bola para a direita, depois para a esquerda, depois para a direita… e nunca acabar. Com fechados, cada estado só é examinado uma vez.

Capítulo 5

Como o código está organizado: o padrão Strategy

O código tem 4 ficheiros. A ideia principal é separar o algoritmo (a receita do capítulo 4) das regras do jogo (capítulo 1).

BestFirstA receita de procura. Não sabe o que é uma bola nem um tubo. É exatamente o mesmo do 8-puzzle do Tutorial 1.
→
IlayoutO "contrato" entre os dois. Diz só que perguntas o algoritmo pode fazer ao jogo.
←
BallSortLayoutAs regras do Ball Sort. Responde às perguntas do contrato.

O contrato Ilayout tem 3 perguntas:

  • children(): "Que estados consigo obter com um movimento?" Responde com a lista de filhos.
  • isGoal(...): "Este estado está resolvido?" Responde sim ou não.
  • getK(): "Quanto custou o movimento que levou aqui?" Responde 1.

O 4.º ficheiro, Main, foi dado pelo professor: lê o input, chama o algoritmo e escreve a resposta.

Analogia

Pensa num GPS. O algoritmo de "encontrar o caminho mais curto" é sempre o mesmo. O que muda é o mapa: Faro, Lisboa, Porto. O BestFirst é o GPS, o BallSortLayout é o mapa, e o Ilayout é o formato que qualquer mapa tem de ter para o GPS o perceber.

Frase para dizer ao professor

"Usei o padrão Strategy do Tutorial 1. O BestFirst ficou igual. Só escrevi uma classe nova, BallSortLayout, que implementa a interface Ilayout com as regras do Ball Sort."

Capítulo 6

Java do zero

Só o que aparece no teu código. Cada lição tem um exemplo pequeno e onde isso aparece no código. Abre uma de cada vez.

1. Variáveis e tiposguardar um valor

Uma variável é uma caixa com nome que guarda um valor. Em Java tens de dizer que tipo de valor vai lá dentro.

int bolas = 3;          // int: número inteiro
double custo = 1.0;     // double: número com casas decimais
char cor = 'R';         // char: UMA letra, entre plicas ' '
boolean cheio = true;   // boolean: verdadeiro (true) ou falso (false)
String linha = "R B E"; // String: texto, entre aspas " "

No teu código: int height é a capacidade, char ball é a cor de uma bola, double g é o custo acumulado.

2. Arraysuma fila de caixinhas

Um array guarda vários valores do mesmo tipo, numa fila numerada a partir de 0. O tamanho fica fixo quando o crias.

int[] size = new int[3];   // 3 caixinhas: size[0], size[1], size[2], todas a 0
size[1] = 2;               // agora size = {0, 2, 0}
int x = size[1];           // x fica com 2
int n = size.length;       // n = 3 (quantas caixinhas tem)

Um array de arrays (char[][]) é uma tabela: tubes[t][k] quer dizer "tubo t, posição k".

char[][] tubes = new char[3][3];   // 3 tubos, cada um com 3 lugares
tubes[0][0] = 'R';                 // fundo do tubo 0 = vermelho
Atenção

Com 3 caixinhas, a última é a 2, não a 3. Por isso o topo de um tubo é size[t] - 1.

3. if, else e o operador ? :decidir
if (size[j] == height) {     // == compara: "é igual a?"
    // o tubo j está cheio
} else {
    // ainda tem espaço
}

Comparações: == igual, != diferente, < menor, >= maior ou igual. Para juntar condições: && quer dizer "e", || quer dizer "ou", ! quer dizer "não".

if (size[j] > 0 && tubes[j][size[j] - 1] != ball)
    // o tubo j tem bolas E a de cima é de outra cor

O ? : é um if numa linha: condição ? valor_se_sim : valor_se_não.

char c = (r < size[t]) ? tubes[t][r] : 'E';
// se há bola na posição r, usa-a; senão escreve E
4. Ciclos for e whilerepetir
for (int i = 0; i < 3; i++) {
    // corre com i = 0, depois i = 1, depois i = 2
}

Lê-se: "começa com i = 0; enquanto i < 3; no fim de cada volta soma 1 a i". i++ é o mesmo que i = i + 1.

for (int r = height - 1; r >= 0; r--)   // conta para trás: 2, 1, 0

O while (condição) repete enquanto a condição for verdade. while (true) repete para sempre, até um return sair do método.

continue salta o resto desta volta e passa à próxima. return sai do método todo.

for (int i = 0; i < 3; i++) {
    if (size[i] == 0) continue;   // tubo vazio: passa ao próximo i
    ...
}

Também há o "for-each", que percorre uma lista: for (State suc : sucs) quer dizer "para cada suc na lista sucs".

5. ++ e -- dentro de expressõeso detalhe mais traiçoeiro

x++ usa o valor de x e depois soma 1. --x subtrai 1 e depois usa o valor.

int s = 2;
tubes[0][s++] = 'R';   // escreve na posição 2, depois s fica 3   → EMPILHAR

int s = 3;
tubes[0][--s] = 0;     // s fica 2, depois apaga a posição 2      → DESEMPILHAR

No teu código: child.tubes[j][child.size[j]++] = ball põe a bola no topo do destino. child.tubes[i][--child.size[i]] = 0 tira a bola do topo da origem.

6. Métodosfunções

Um método é um bloco de código com nome que pode receber valores e devolver um resultado.

public double getK() {   // devolve um double, não recebe nada
    return 1;
}

public boolean isGoal(Ilayout l) {   // recebe um Ilayout, devolve true/false
    ...
}

O tipo antes do nome (double, boolean, List<Ilayout>) é o que o método devolve. O que está entre parênteses é o que recebe.

7. Classes, objetos, new e construtormoldes e coisas

Uma classe é um molde. Um objeto é uma coisa feita com esse molde. new cria um objeto.

BallSortLayout inicio = new BallSortLayout("R B E\nB B E\nR R E\n");
// cria um estado a partir do texto

O construtor é o método especial que corre quando fazes new. Tem o nome da classe e não tem tipo de retorno. É onde se preparam os campos.

Os campos são as variáveis de cada objeto: cada estado tem os seus próprios tubes e size.

private: só a própria classe mexe. public: qualquer um pode usar. static final: uma constante, igual para todos (EMPTY = 'E').

this quer dizer "este objeto". this.height = height copia o valor recebido para o campo do objeto.

8. Interfaces e implementscontratos

Uma interface é uma lista de métodos sem código: só diz "quem me implementar tem de ter isto".

interface Ilayout {
    List<Ilayout> children();
    boolean isGoal(Ilayout l);
    double getK();
}

class BallSortLayout implements Ilayout { ... }   // "cumpro o contrato"

Graças a isto, o BestFirst pode trabalhar com qualquer Ilayout: um Board do 8-puzzle ou um BallSortLayout. É o padrão Strategy.

9. null"nada"

null quer dizer "não aponta para nenhum objeto".

  • O estado inicial tem father = null: não tem pai.
  • O Main chama solve(..., null): não há um objetivo concreto, só a regra do isGoal.
  • O solve devolve null quando não há solução; o Main escreve então "no solution found".
10. Listas, mapas e conjuntoscoleções que crescem
List<Ilayout> filhos = new ArrayList<>();   // lista que cresce
filhos.add(x);                               // acrescenta no fim

Map<Ilayout, State> fechados = new HashMap<>();   // dicionário chave → valor
fechados.put(estado, s);                           // guarda
fechados.containsKey(estado);                      // "já tens esta chave?" → true/false

Set<Ilayout> emAbertos = new HashSet<>();   // conjunto sem repetidos
emAbertos.add(estado);
emAbertos.contains(estado);                 // "já está cá?"

O que está entre < > diz o tipo do que vai lá dentro. HashMap e HashSet respondem a "já está cá?" de imediato, mesmo com milhares de estados.

11. PriorityQueue e lambdaa lista abertos

Uma PriorityQueue é uma fila onde sai sempre primeiro o elemento "menor". Tens de dizer o que é "menor".

abertos = new PriorityQueue<>(10,
    (s1, s2) -> (int) Math.signum(s1.getG() - s2.getG()));

A parte (s1, s2) -> ... é uma lambda: uma função curta escrita no sítio. Recebe dois estados e devolve um número negativo se s1 tem menor g, positivo se tem maior, 0 se é igual. Ou seja: "o de menor g sai primeiro".

abertos.add(s);       // entra na fila
abertos.remove();     // tira o de menor g
abertos.isEmpty();    // está vazia?
12. equals e hashCode"são iguais?"

Por defeito, o Java só acha dois objetos iguais se forem o mesmo objeto na memória. Mas dois estados com as mesmas bolas nos mesmos sítios devem contar como iguais, mesmo criados em momentos diferentes.

equals ensina ao Java quando dois estados são iguais: mesmas bolas, mesmas posições. hashCode dá um número a cada estado; estados iguais têm de dar o mesmo número. O HashMap e o HashSet usam os dois.

Exemplo

Do estado A move-se um azul para a direita e depois para a esquerda: volta-se ao estado A, mas é um objeto novo. Graças ao equals, o programa percebe que já o viu e não o examina outra vez.

13. clonecopiar a sério

Em Java, int[] b = a; não copia o array: a e b passam a ser dois nomes para as mesmas caixinhas. Mexer em b muda a.

int[] a = {1, 2};
int[] b = a;          // mesmas caixinhas!
b[0] = 9;             // agora a = {9, 2} também
int[] c = a.clone();  // caixinhas novas: mexer em c não muda a

No teu código: cada filho começa com clone(), que copia cada tubo. Sem isso, mexer no filho estragava o pai.

14. Classe dentro de classe e IteratorState e o caminho

static class State está dentro de BestFirst. Fora dela chama-se BestFirst.State. É só uma classe auxiliar arrumada lá dentro.

Um Iterator percorre uma sequência, um elemento de cada vez:

while (it.hasNext()) {          // ainda há mais?
    BestFirst.State i = it.next(); // dá-me o próximo
}

O solve devolve um Iterator sobre o caminho. O Main percorre-o e escreve o g do último.

Para cada tubo (coluna)…

char c = cells[t].charAt(0);

if (c != EMPTY) tubes[t][size[t]++] = c;
